The implementation is strong, but the staged build left too many representations of the same FREEFORM design. I would simplify the frontend contract now and fix two station-sampling inconsistencies before merging.

## A. Simpler / better, ranked

1. **Create one canonical frontend FREEFORM model/codec.** Interior-point normalization is independently implemented in [freeformParams.js:18](<https://github.com/m3gnus/waveguide-generator/blob/v1/src/config/freeformParams.js:18>), [paramPanel.js:157](<https://github.com/m3gnus/waveguide-generator/blob/v1/src/ui/paramPanel.js:157>), [freeformProfileEditor.js:75](<https://github.com/m3gnus/waveguide-generator/blob/v1/src/ui/freeformProfileEditor.js:75>), and [waveguidePayload.js:74](<https://github.com/m3gnus/waveguide-generator/blob/v1/src/solver/waveguidePayload.js:74>), with migration invoked again during preparation and state loading at [params.js:223](<https://github.com/m3gnus/waveguide-generator/blob/v1/src/geometry/params.js:223>) and [state.js:56](<https://github.com/m3gnus/waveguide-generator/blob/v1/src/state.js:56>). Keep the final flat UI model, but give it one normalize/validate/serialize module; this deletes the branch-only `profileH/profileV` migration, three duplicate point normalizers, duplicated sorting/filtering, and much of the FREEFORM special code in `paramPanel`; risk is only losing developers’ persisted pre-W3 localStorage designs.

2. **Retain per-ring azimuth sampling, but drive it from the active station span rather than the mouth.** The current branch chooses the entire structural angle family solely from `geometry.stations[-1]` at [profile_sampling.py:704](<https://github.com/m3gnus/hornlab-waveguide-mesher/blob/main/hornlab_mesher/profile_sampling.py:704>) and applies that mouth descriptor to every ring at [profile_sampling.py:743](<https://github.com/m3gnus/hornlab-waveguide-mesher/blob/main/hornlab_mesher/profile_sampling.py:743>); replace the mouth-specific block with one resolver shared by outline evaluation, corner-radius validation, and angle generation. This deletes the `mouth_base/mouth_span/mouth_station` assumptions and makes arbitrary station schedules honest; risk is maintaining constant row identity when the active shape changes, so quadrant and acoustic-fit tests need mixed ellipse/rounded-rectangle schedules.

3. **Make `_validate_freeform_config` the only canonical feature gate after config normalization.** FREEFORM exclusions are checked once in `_validate_formula_features` at [config_builder.py:453](<https://github.com/m3gnus/hornlab-waveguide-mesher/blob/main/hornlab_mesher/config_builder.py:453>), again after `common` is assembled at [config_builder.py:1103](<https://github.com/m3gnus/hornlab-waveguide-mesher/blob/main/hornlab_mesher/config_builder.py:1103>), and again from the direct point-grid path at [profile_sampling.py:698](<https://github.com/m3gnus/hornlab-waveguide-mesher/blob/main/hornlab_mesher/profile_sampling.py:698>). Keep the ingest-only rejection of foreign coefficient keys, normalize aliases into `common`, and delete the FREEFORM branch in `_validate_formula_features`; risk is changed error timing/text for hand-written configs.

4. **Use backend-authoritative diagnostics while retaining the JS curve only for optimistic dragging.** The browser mirrors PCHIP/Hermite and inflection detection in [freeformCurve.js:13](<https://github.com/m3gnus/waveguide-generator/blob/v1/src/geometry/freeformCurve.js:13>) and [freeformCurve.js:192](<https://github.com/m3gnus/waveguide-generator/blob/v1/src/geometry/freeformCurve.js:192>), although the viewport already returns the mesher report at [mesher_adapter.py:721](<https://github.com/m3gnus/waveguide-generator/blob/v1/server/solver/mesher_adapter.py:721>); metadata is then discarded by [scene.js:86](<https://github.com/m3gnus/waveguide-generator/blob/v1/src/app/scene.js:86>). Pass metadata and authoritative H/V samples to the editor after each response and delete the JS inflection implementation; risk is diagnostic highlighting lagging during a drag, so the local curve should remain as an uncommitted preview.

5. **Build formula-specific payloads positively, not by building everything and deleting keys.** FREEFORM currently receives the generic analytic payload and removes a growing list afterward at [waveguidePayload.js:289](<https://github.com/m3gnus/waveguide-generator/blob/v1/src/solver/waveguidePayload.js:289>), while supported-formula lists are repeated in three routes and solve validation at [routes_mesh.py:59](<https://github.com/m3gnus/waveguide-generator/blob/v1/server/api/routes_mesh.py:59>), [routes_mesh.py:127](<https://github.com/m3gnus/waveguide-generator/blob/v1/server/api/routes_mesh.py:127>), [routes_mesh.py:187](<https://github.com/m3gnus/waveguide-generator/blob/v1/server/api/routes_mesh.py:187>), and [simulation_validation.py:93](<https://github.com/m3gnus/waveguide-generator/blob/v1/server/services/simulation_validation.py:93>). Use a common transport block plus one serializer per formula and a shared `Literal`/enum server-side; this deletes the FREEFORM deletion list and route gates, with the modest risk of changing API validation wording.

6. **Remove unpublished compatibility aliases.** `cornerRatio` remains beside the final millimetre model through [freeform.py:703](<https://github.com/m3gnus/hornlab-waveguide-mesher/blob/main/hornlab_mesher/freeform.py:703>) and a “legacy ratio” UI at [paramPanel.js:973](<https://github.com/m3gnus/waveguide-generator/blob/v1/src/ui/paramPanel.js:973>), while `inflectionPolicy="allow"` is explicitly identical to `"warn"` in [test_freeform_core.py:591](<https://github.com/m3gnus/hornlab-waveguide-mesher/blob/main/tests/test_freeform_core.py:591>). Standardize on `cornerRadiusMm` and `warn|reject`; this deletes mixed corner branches, legacy UI/tests, and a meaningless policy/cache dimension, with risk only to configs created on this unmerged branch.

## C. Correctness watch, ranked

1. **Absolute corner radius is silently changed between stations.** Validation checks `cornerRadiusMm` only at station locations at [freeform.py:975](<https://github.com/m3gnus/hornlab-waveguide-mesher/blob/main/hornlab_mesher/freeform.py:975>), but evaluation silently clamps it to `min(a,b)` everywhere at [freeform.py:759](<https://github.com/m3gnus/hornlab-waveguide-mesher/blob/main/hornlab_mesher/freeform.py:759>). A verified schedule with valid 10 mm endpoint corners and a 4 mm intermediate waist evaluates with a 4 mm corner, contradicting the absolute-mm/hold contract; validate the full active span or reject it instead of clamping.

2. **Intermediate rounded rectangles are not structurally sampled unless the mouth is also rounded.** The selector at [profile_sampling.py:706](<https://github.com/m3gnus/hornlab-waveguide-mesher/blob/main/hornlab_mesher/profile_sampling.py:706>) falls back to a fixed ordinary angle list when the mouth is elliptical. In a verified rounded-rectangle-at-`t=.5`, ellipse-at-mouth case, neither analytic tangency was present in the `phi_grid`; existing grid tests use a rounded-rectangle mouth at [test_freeform_grid.py:32](<https://github.com/m3gnus/hornlab-waveguide-mesher/blob/main/tests/test_freeform_grid.py:32>).

3. **Changing length can make the editor and backend describe different curves.** The editor retains every interior anchor when assembling its displayed curve at [freeformProfileEditor.js:236](<https://github.com/m3gnus/waveguide-generator/blob/v1/src/ui/freeformProfileEditor.js:236>), while payload assembly silently removes anchors outside the new length at [waveguidePayload.js:99](<https://github.com/m3gnus/waveguide-generator/blob/v1/src/solver/waveguidePayload.js:99>). Verified example: shortening to 40 mm left a visible 60 mm anchor in state while the payload contained only throat and mouth.

4. **Explicit CircSym can accept non-axisymmetric FREEFORM tangents.** The server compares only H/V point rows at [axisymmetry.py:102](<https://github.com/m3gnus/waveguide-generator/blob/v1/server/solver/axisymmetry.py:102>) and ignores block-level mouth/throat angles and tangent scales. A verified payload with identical points but H/V mouth angles of 30°/60° returned no rejection reasons; explicit CircSym should use the same mesher-authoritative probe already used by auto mode at [axisymmetry.py:38](<https://github.com/m3gnus/waveguide-generator/blob/v1/server/solver/axisymmetry.py:38>).

5. **The displayed S-curve span is not the mesher’s convention.** Python uses exact spline derivatives over 4001 parameter samples at [freeform.py:1021](<https://github.com/m3gnus/hornlab-waveguide-mesher/blob/main/hornlab_mesher/freeform.py:1021>), while JS differentiates a roughly 96-point resampled polyline at [freeformCurve.js:192](<https://github.com/m3gnus/waveguide-generator/blob/v1/src/geometry/freeformCurve.js:192>). For one existing test profile, JS reported `50.000..79.101 mm / 23.51°` while Python reported `50.000..80.138 mm / 24.20°`; close visually, but fragile at the 1° policy threshold.

6. **Contract skew can still discard new fields silently.** The nested Pydantic models have no `extra="forbid"` at [contracts/__init__.py:390](<https://github.com/m3gnus/waveguide-generator/blob/v1/server/contracts/__init__.py:390>) and [contracts/__init__.py:409](<https://github.com/m3gnus/waveguide-generator/blob/v1/server/contracts/__init__.py:409>), and viewport metadata generation swallows every exception at [mesher_adapter.py:721](<https://github.com/m3gnus/waveguide-generator/blob/v1/server/solver/mesher_adapter.py:721>). A frontend/backend or server/mesher version mismatch can therefore lose an optional field or diagnostic without exposing the actual contract problem; forbid unknown FREEFORM nested fields and return a small contract-version marker.
