# Phase 1, Batch B — binary frame codec (both languages) + fixtures + fuzz corpus

Implement FRAME-SPEC v1.1 (`docs/FRAME-SPEC.md` — read it fully; it is the contract, including the v1.1 "Preview surfaces, normals, and fidelity" section) in this repo.

**Path discipline (other agents work in this repo concurrently): you may create/modify ONLY `server/protocol/**`, `shared/**`, and `server/tests/test_frame_*.py`. Touch nothing else — not docs/, not spike/, not server/design/.**

Runtime: Python via `../Waveguide Generator/.venv/bin/python` (numpy, pytest available; no new deps). JavaScript via `node` — plain ES modules (`.mjs`) with JSDoc types, `node --test` for tests, no build step, no npm installs.

## Deliverables

1. `server/protocol/__init__.py`, `server/protocol/frame.py` — encoder + decoder:
   - `encode(header_fields: Mapping, arrays: Mapping[str, np.ndarray]) -> bytes` and `decode(data: bytes) -> tuple[Header, dict[str, np.ndarray]]` (decode returns zero-copy views).
   - Enforce EVERY validation rule in FRAME-SPEC §"Validation rules" (magic, header bounds, section bounds/overlap/dtype/shape arithmetic, size ceilings, index spot-check) and the v1.1 rules (normals required per rendered surface, row-aligned, finite, unit length within 1e-3; `surfaces` model with roles/shading/normalMethod; fidelity metadata passthrough).
   - Encoder refuses non-finite positions/normals; 8-byte section alignment; sections in header order.
2. `shared/js/frame.mjs` — decoder only, mirroring every validation rule; returns typed-array views; small, dependency-free.
3. `shared/frame-fixtures/` — generated by `shared/gen_fixtures.py` (runnable with the venv python):
   - ≥4 GOOD fixtures: minimal single-surface preview; multi-surface preview with normals + fidelity metadata (realistic horn-ish grid data is fine to synthesize); a curve frame; a result-chunk frame.
   - A MALFORMED corpus: one file per validation rule violated (bad magic, truncated header, overlapping sections, dtype/shape mismatch, oversize, missing normals on a rendered surface, non-unit normals, out-of-range indices…), each named for its rule.
   - `manifest.json` describing each fixture and the expected outcome (`ok` or the expected error code/rule id).
4. Tests, both consuming the SAME fixtures via the manifest:
   - `server/tests/test_frame_spec.py` (pytest): round-trip on good fixtures (byte-exact re-encode where deterministic), every malformed fixture rejected with the right rule, plus property-style fuzz (random truncations/bit flips of good fixtures never crash the decoder — always a clean error).
   - `shared/js/frame.test.mjs` (`node --test`): decodes all good fixtures to the same shapes/values (spot-check a few values against manifest-recorded expectations), rejects every malformed fixture, same fuzz approach.
5. Error taxonomy: a small shared list of rule ids (e.g. `bad-magic`, `section-overlap`, `normals-missing`) used in both implementations and the manifest, defined once in `shared/frame-rules.json`.

## Rules

- The Python encoder is the reference; the JS side never encodes (tests may byte-compare against fixture files only).
- Self-verify: run both test suites; iterate until green. Report counts.
- Final message: files created, test counts both languages, any FRAME-SPEC ambiguities you hit and how you resolved them (list them explicitly — the spec author will review).
