# ABEC artifacts — preservation copy, placement undecided

**Do not merge this branch as a considered layout.** `docs/validation/` is where these
files were put to get them into git today, not a decision that this is where they belong.
Moving them later is a `git mv`; if they should live in their own repository instead, this
branch is simply never merged and the content is copied out of it.

## Why the hurry

Both directories lived only in the workspace root's `benchmarks/`, which is not a git
repository. They existed on exactly one disk, with no remote and nothing to notice their
loss. `abec-g8-circsym-ib/` is the first genuinely external validation this stack has —
its whole value is that someone else can re-run it — and `wg2/docs/validation/SOLVER-QUALIFICATION.md`
asks an external reference to "retain enough source geometry and solver metadata for
independent reproduction". A reference on one unmanaged disk is not retained; it is a
claim.

## What is here

### `abec-g8-circsym-ib/` — the G8 fixture, solved

An ABEC3 CircSym infinite-baffle project for an axisymmetric OS-SE waveguide, its solved
spectrum, and the harness that compares our engine against it. Result, 2026-09-03:
absolute SPL rms 0.009 / 0.050 / 0.099 / 0.192 dB by band, pattern rms 0.005 / 0.107 /
0.230 / 0.303 dB, radiation impedance median relative error 0.0017. Its own `README.md`
carries the conventions, the origin convention, and the two findings it exposed.

Entirely text apart from `fixture-meridian.png` (58 KB), a matplotlib plot of the meridian
with equal axis scaling, generated by this session and regenerable from `nodes.txt`. It is
included deliberately rather than blindly: it is the only thing that answers "does this
geometry look right" without opening ABEC.

`__pycache__/` was excluded.

### `abec-rerun/` — the corrected ASRO projects, from 2026-07-31

The projects behind the `Sym=` correction: the shipped ASRO reference paired `Sym=xy`
with a full 4-quadrant mesh, which ABEC reads as "mirror and complete" and therefore
solves as four superimposed copies, with no error and no warning.

- `A_asro68_full_nosym/` — full mesh, no `Sym` clause. **Solved**, `Results/Spectrum_ABEC.txt`.
- `B_asro2_quarter_sym/` — the `yz+xz` quarter with `Sym=xy`. **Solved**.
- `C_fine_quarter_sym/`, `D_fine_quarter_hf/` — prepared 2026-07-31 and **never solved**.
  Almost certainly because ABEC3 has no command line and the solve is a manual F5/F7, the
  same wall that made G8 a two-party job. They are still worth a sitting.

All meshes are ASCII gmsh 2.2. `C_fine_quarter_sym/FINE1.msh` and
`D_fine_quarter_hf/FINE1.msh` are byte-identical (md5 `956001a7…`); they differ only in
`solving.txt`, which is the point of having both.

Largest files: two 694 KB meshes, one 542 KB mesh, two 182 KB spectra. 2.6 MB total, all
text.

## Running any of them

ABEC3 Pro v360b07 exposes no command line and its UI is invisible to UI Automation, so an
agent can build these projects but cannot solve them. Open `Project.abec`, press **F5**
(Solving), then **F7** (Spectra), then export to `Results/Spectrum_ABEC.txt`.
