# G8 — external ABEC reference, axisymmetric waveguide in an infinite baffle

An ABEC3 CircSym project built to close the external-reference gap recorded in
`wg2/docs/validation/SOLVER-QUALIFICATION.md` ("External axisymmetric reference
status"). Until this is solved, every infinite-baffle claim in the stack rests on
our own three formulations agreeing with each other.

**Status: solved 2026-09-03.** `Results/Spectrum_ABEC.txt` holds all three
quantities over 100 log-spaced frequencies. Physics sanity: the normalized throat
radiation resistance climbs from 0.0013 at 200 Hz to 1.03 at 20 kHz, i.e. the
horn reaches plane-wave loading, which is what a working waveguide model should
do and a broken one generally does not.

## Why this fixture satisfies the requirements the doc sets

The doc refuses two earlier candidates: one with azimuth-dependent geometry, and
one with an unresolved mounting-plane intersection. This one is neither.

- **Body of revolution, demonstrably.** ABEC solves it in `Dim=CircSym`, whose
  entire input is one meridian polyline (`nodes.txt`). Axisymmetry is not a
  property we assert about a 3-D mesh; it is the only geometry the solver is
  given.
- **Flush mounted, with a valid interior/aperture interface.** `solving.txt`
  declares `Infinite_Baffle Subdomain=2; Position=Pos offset=120.000mm`, and
  element 121 (nodes 121→122, `Subdomain=1,2`) is the aperture disc lying exactly
  in that plane, running from the mouth rim (z=120, r=157.566) to the axis
  (z=120, r=0). The horn interior and the driver dome are the interior subdomain;
  the exterior subdomain is the half space in front of the baffle. There is no
  geometry behind the baffle, which is ABEC's requirement for an infinite baffle
  and the reason the interface has to exist at all.
- **Reproducible from source.** `g8_osse_circsym_ib.cfg` is the ATH definition it
  was generated from (ATH V2025-06), `ath-config-as-run.txt` is the config ATH
  echoed back, and the whole ABEC project is text — no binary mesh.

## Analysis setup

| | |
|---|---|
| `Dim` | CircSym |
| Frequencies | 200 Hz – 20 kHz, 100 points, log |
| `MeshFrequency` | 40000 Hz — ATH's guidance for a 20 kHz CircSym run; ABEC subdivides the polyline to suit, including the single 157.566 mm interface element |
| Drive | `DrvType=Acceleration; Value=100` on the throat dome, DrvGroup 1001 |
| Observation | polar 0–90°, 19 points, `Distance=2m`, `Offset=120mm`, `BasePlane=Pos` |

**Origin convention — read this before comparing.** The polar arc is centred at
`Offset=120mm`, i.e. **on the baffle plane at the mouth**, not at the throat.
This is the opposite of the free-standing ASRO reference, where ABEC measures
from the throat and using the mouth was worth 1.4 dB at 100 Hz. ATH clamps this
offset to the mouth plane itself and says so in its output (`-IB offset set to
120.000 mm`); an offset behind the baffle would put the wide-angle observation
points in a region the model does not solve.

Two spectra come out of one solve:

- `PM_SPL` — `NormalizingAngle=0`, so pattern only, absolute level removed.
- `PM_SPL_ABS` — no normalizing angle, so absolute level. Added deliberately:
  the normalized polars cannot catch a level or drive-convention error, which is
  exactly the class of mistake an external reference is for.

`RadImp` gives the normalized throat radiation impedance, a second absolute
quantity that is independent of the observation geometry entirely.

## Running it

ABEC3 exposes no command line and its UI is invisible to UI Automation, so this
is a manual step (ABEC3 Pro v360b07, `ABEC3_Pro_64r.exe`):

1. Open `Project.abec`.
2. **F5** — Solving → Start Solving.
3. **F7** — Spectra → Start calculation.
4. Export the spectra to `Results/Spectrum_ABEC.txt`, matching the layout of the
   existing references under `benchmarks/abec-rerun/`.

## Comparing against it

- Feed our solvers **the polyline in `nodes.txt`**, not the analytic OS-SE curve.
  ABEC subdivides its truncated cones linearly, so the surface it solves lies on
  these segments; resampling the underlying curve instead would compare two
  different bodies and charge the difference to the solver.
- ABEC uses constant (order 0) elements collocated at element centroids; we use
  P1 continuous. Different, convergent, and the reason a fine mesh matters more
  than usual here.
- ABEC's time convention is e^-jkr against bempp's e^+ikr — conjugate before
  comparing phase.
- ABEC defaults: c = 343.32 m/s, rho = 1.205. Non-uniqueness compensation is on
  by default when `NUC=` is unspecified, as it is here.
- `Spectrum_ABEC.txt` layout, as exported here: three `Data` sections keyed by
  `Graph_Caption` (`RadImp`, `PM_SPL`, `PM_SPL_ABS`). Each row is
  `frequency, (re, im) x 19` — one complex pair per polar angle, 0° first, in
  the order given by `PolarRange`. Decimal separator is `.` in this export;
  the older ASRO reference files use `,`, so a reader must handle both.

## Result, 2026-09-03

`compare.py` against `hornlab_metal_bem` 0.1.0 (pin `368849cc`), element cap
4.29 mm — ABEC's own λ/2 at `MeshFrequency=40000`:

| quantity | <1 kHz | 1–4 kHz | 4–11 kHz | >11 kHz | max |
|---|---|---|---|---|---|
| absolute SPL, rms dB | 0.009 | 0.050 | 0.099 | 0.192 | 0.945 |
| pattern, rms dB | 0.005 | 0.107 | 0.230 | 0.303 | 0.894 |

−6 dB half-angle agrees within 0.15°–0.87° from 1 kHz to 20 kHz. Normalized
throat radiation impedance: median relative error 0.0017, max 0.0093.

**The external gap is closed for the axisymmetric infinite baffle.** Absolute
level, not only pattern, is confirmed against a solver outside this stack.

Halving the element cap to 2.15 mm moves the >11 kHz numbers (SPL 0.192 → 0.131,
pattern 0.303 → 0.191) and barely moves anything below 4 kHz, so the HF residual
is our discretisation, not a formulation difference. Quote the converged numbers
if you need HF figures.

### Two things this turned up

**Our CircSym engine conjugates ABEC.** Real parts of the radiation impedance
agree to under 0.5% while the imaginary parts are equal and opposite at every
frequency, which is a time-convention flip and nothing else. `compare.py`
conjugates ours into ABEC's before any phase-bearing comparison. Worth noting
that `SolveResult`'s docstring claims e^(−iωt) and ABEC's manual claims e^(−jkr);
those cannot both be true as written, and one of the two docs is wrong.

**`hornlab_metal_bem` hardcodes the sound speed.** `_constants.SPEED_OF_SOUND`
is 343.0 m/s with no `SolveConfig` knob, against ABEC's 343.32 — 0.093% apart,
and an odd asymmetry given `air_density` is configurable. It is far too small to
explain anything above, but it is a fixed bias in every comparison this stack
makes against ABEC.

### The trap worth remembering

ATH emits the aperture interface as **one 157.6 mm element**, because ABEC
refines its own input from `MeshFrequency` and ATH knows that. Our solver does
not refine. Handed the file as-is, our interior stays fine-meshed and nearly
correct — radiation impedance still lands within a few percent — while the
radiated field collapses: the −6 dB half-angle came out 3.9° against ABEC's 45.6°
at 10 kHz, a 40 dB pattern error from one bad element. `subdivide()` splits along
ABEC's own segments, so the body is unchanged. Any harness feeding an ABEC mesh
to our solvers has to do this first.
