## Design Specificity Verdict

**The workspace shell is strongly grounded in this product. Three surfaces are
not, and they are the ones the user touches at the highest-stakes moments.**

**Authored for this product:** the parameter row is a genuinely invented
component — prose name, italic ATH symbol, right-aligned monospace value,
inline unit, and a 1px range-position track in a 30px row, with the
Symbol-Holds rule actually implemented (`(R)` never truncates while "Mouth
radius" does). The state-badge family, the `next · 260810_horn_v19` name
preview, and `connected · 31/31 shown` are instrument idioms, not SaaS idioms.

**Category-interchangeable:**
- **The Settings dialog is a different design system** — bordered fieldsets
  around checkbox groups (DESIGN.md's explicit Don't), native checkbox chrome,
  two competing heading idioms, ~36px controls against the workspace's 26px,
  and a 730px text field for the value `horn`. Droppable into any B2B SaaS.
- **The results-card affordances are generic-invisible** — the chart-type
  `<select>` and the expand/close buttons are `opacity: 0` at rest with no
  chevron and no rest state. That is a marketing card-grid pattern applied to
  the six most useful controls in a measurement tool.
- **The SIMULATION rail drifts from the GEOMETRY rail** — different control
  widths, so labels clip at a different point; no ATH symbol to protect; one
  parameter gets a three-line inline paragraph no other parameter gets.

**Deterministic scan:** static source tree exit 0, zero findings. URL scan 84
findings across 10 rules; 79 are covered by recorded waivers in
`.impeccable/config.json` with their measurements. In-page overlay injection
succeeded (live-server on :8400, console reported 83 anti-patterns, server
stopped). Five findings sit outside the waiver file:
`gpt-thin-border-wide-shadow` ×4 (advisory) and `flat-type-hierarchy` ×1.

**Detector agreed with the review** on nothing new — the two assessments found
almost disjoint problems, which is the useful result: the deterministic rules
are saturated on this codebase, and everything that remains is judgment.

**Detector caught what the review missed:** one genuine unwaived contrast
failure that neither my earlier audit nor Assessment A found — the `¾`
view-preset button in the viewport toolbar, light theme only,
`rgb(0,105,165)` on `rgb(216,226,229)` = **4.45:1**, 0.05 short of AA. Its

**Verified false positives:** the `low-contrast` finding on the Solve button's

## Overall Impression

The instrument itself is very good and the chrome around it is not finished.
The parameter rail, the badge row, the token system, and both themes are the
work of someone who knows what this tool is for. Everything that happens when
something goes wrong — an invalid value, a failed export, a screen reader, a
second run to compare against — is unfinished. The single biggest opportunity
is that **comparing two runs, which PRODUCT.md names as the definition of
success, is currently unreadable.**

## What's Working

1. **The parameter row is invented, not borrowed.** It is shaped around how
   this user reads: symbol column, then value column, prose as fallback.
2. **Both themes are real, and the numbers prove it.** Every sampled text role
   clears 6.3:1 in dark; light is warm paper with signal hues re-derived
   against it rather than reused. Most products claim this and don't keep it.
3. **The command palette is a correctly-built combobox** — `role="combobox"`,
   live `aria-activedescendant`, `role="option"` + `aria-selected`, modal
   dialog semantics, and a visible key legend. Rare to see done completely.

## Priority Issues

**[P0] Comparing two runs is unreadable — the headline capability.**
Both toolbar chips render `260308trit…`; both SPL legend entries render `260…`;
and DIR H, DIR V, IMPEDANCE and SUMMARY keep showing one run with no indication
which, and no indication that compare does not apply to them.
*Fix:* middle-ellipsize run names so the version suffix survives; put the run
name in every chart legend; give single-run charts an explicit state so the
absence is deliberate rather than invisible. → `/impeccable clarify`

**[P0] Eighteen result-dock controls are `opacity: 0`, including when focused.**
Six chart cards × (an 8-option chart-type select + expand + close). A keyboard
user tabs through 18 controls with no visible focus indicator at all, because
the ring is drawn on a transparent element. A new user cannot discover that the
word "SPL" is a dropdown. Targets are 13px and 19×19px, both under 24px.
*Fix:* persistent chevron and a low-contrast rest state; full opacity on hover
**and** `:focus-visible`; 24px hit areas. → `/impeccable harden`

**[P1] An invalid value discloses nothing and disarms nothing.**
`99999` in Mouth radius gets `aria-invalid="true"` and a red border, and that is
the entire feedback: no range anywhere in the UI, no `aria-errormessage`, and
the `--fill` track freezes at its last valid position, so the one range
affordance actively lies. Solve stays enabled at full cyan; the badge keeps
saying LIVE over geometry that does not match the field — which is exactly what
Product Principle 1 forbids. → `/impeccable harden`

**[P1] Screen-reader users get no structure and no announcements.**
Zero headings in the workspace (`h1`–`h6` returns empty outside the Settings
dialog). 209 tab stops, ~124 of them in the jobs rail. The 3D canvas is
`tabindex="0"` with no role and no name. Run state is a bare coloured dot with
no text alternative — the system's own Signal Rule, violated. The only
`aria-live` regions belong to dockview, so a solve landing and repainting every
chart is silent. → `/impeccable harden`

**[P2] The Settings dialog is a different product, and Log leaves the product.**
The dialog uses bordered fieldsets, native checkbox chrome, two heading idioms,
~36px controls, and two verbatim-identical 11-format checkbox grids that differ
only by header. Separately, the run card's **Log** button navigates the whole
SPA to a plain-text endpoint, in an application whose premise is a single window
that never navigates. → `/impeccable distill`

## Persona Red Flags

**Alex (impatient power user).** ⌘K → "solve" ranks the Solve command 17th,
behind 16 fuzzy parameter matches. Arrow keys do nothing on a focused number
field — the fine-adjust gesture is a mouse-only label scrub, so nudging 1 mm
means select-all and retype. In the layout the app loaded with, the jobs rail
gave run names 44.8px for strings needing 55–187px, so `horn_v18`, `horn_v17`
and `horn_v16` all rendered as the identical string `horn_…`, disambiguated
only by a timestamp — and two runs shared `10:49`.

**Sam (keyboard + screen reader + 200% zoom).** No headings, no skip links, 209
tab stops. Eighteen invisible focusable controls in the results dock. Number
fields are `type="text"` with no `role="spinbutton"` and no
`aria-valuemin/max/now`, so the range information encoded in the fill track is
available to sighted users and to nobody else. Tooltips are `mouseover`-only
and not linked by `aria-describedby`, so every truncated label
(`Measuremen…`, `Normalizatio…`, `Throat cover…`) is unresolvable by keyboard.
At 200% zoom all five panels collapse into one tab group — content stays
reachable, so it is not a reflow failure, but the core "turn a number, watch the
shape respond" loop is no longer available at all.
*Credit:* the global focus ring is real and strong, the theme control is a
proper `aria-pressed` group, and dark-theme text never dropped below 6.38:1.

**Riley (deliberate stress tester).** Narrow to 640px and widen back: two
uncaught `TypeError: …reading 'layerStack'` from echarts, and three panels paint
as blank white rectangles for over a second. The DOM is intact — it is a paint
failure that self-heals — but nothing acknowledges the exception. The compare
dropdown contains five runs named `horn_1`, two `horn_v01`, two `horn_v04`, two
`horn_v05`; the ledger previews the *next* name but does not prevent collisions
among existing ones. `Export (0)` is disabled with a tooltip that explains what
it would do and never mentions that the fix lives in a preferences popover.

## Minor Observations

- `request→paint >999 ms` is a clamp presented as a measurement, beside a real
  one (`server 0.2 ms`), and it never changed across a parameter edit or a
  reload — stale numbers in the badge row whose job is to prove nothing is stale.
- Dash inconsistency: status bar `400 Hz – 16 kHz` (en) vs SUMMARY
  `50 Hz — 20.0 kHz` (em).
- `Sweep start` / `Sweep end` appear twice in the SIMULATION rail — Hz under
  FREQUENCY SWEEP, degrees under DIRECTIVITY MAP — disambiguated only by unit.
- `Design name` / `Next version` are editable in two places with no indication
  they are the same value.
- The directivity colormap changes with the UI theme, so the same dB value
  renders magenta-family in dark and green/blue-family in light: two
  screenshots of one run are not comparable.
- `Export theme` offers ten named themes in a product shipping two first-class
  UI themes, and their naming voice is more expressive than the interface's.

## Questions to Consider

1. The status bar says the sweep is `400 Hz – 16 kHz · 20 f`; the SUMMARY card
   says `50 Hz – 20.0 kHz · 40 f`. Which one am I about to spend six minutes
   solving, and why does the instrument make me infer that rather than tell me?
2. The Indicator Rule says cyan is legal on "something the system reports as
   live." So what is the green `Latest` chip? It is the most live thing on
   screen, in a different hue, geometry and case from the LIVE badge 40px above.
3. Six chart cards each conceal an eight-way selector at `opacity: 0`. If that
   control is worth building, why is it a secret — and if it is a secret, why is
   it a tab stop with no focus indicator?
4. Twenty-eight runs, five named `horn_1`. Why does an instrument careful enough
   to preview the next name not refuse to reuse one?
