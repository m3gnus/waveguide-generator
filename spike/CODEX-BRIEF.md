# Phase 0 spike — implementation brief

You are implementing the Phase 0 de-risk spike for the Waveguide Generator v2 rebuild. Throwaway-quality is acceptable; measured numbers are the product. Work ONLY inside `spike/` of this repo (`waveguide-generator-v2`). The v1 app lives at `../Waveguide Generator` (note the space) — **read-only**: never write there, open its SQLite DB with `sqlite3` URI `file:...?mode=ro`.

## Ground truth you need

- v1 backend venv: `../Waveguide Generator/.venv` (Python 3.13, fastapi 0.136, uvicorn 0.49, websockets 16, numpy 2.4.6, scipy 1.17). All spike Python runs with THAT venv's python. Do not pip-install anything into it.
- The preview entry point: `build_viewport_geometry(payload)` in `../Waveguide Generator/server/solver/mesher_adapter.py` (line ~680). It normalizes a frontend payload via `waveguide_payload_to_mesher_config` and calls the mesher's gmsh-free canonical viewport API, returning `{formula, mode, params, grid, enclosure, metadata}` where `grid` holds point arrays shaped by `grid_n_phi × grid_n_length` (see `_reshape_point_grid`, `_rounded_viewport_grid`). Import it by inserting `../Waveguide Generator/server` into `sys.path` (also check what else `server/solver/__init__.py` pulls in — import the module in the cheapest way that works; `solver_bootstrap` must NOT be triggered if avoidable).
- LOD knobs: `payload.mesh.angularSegments` / `payload.mesh.lengthSegments` (clamped by constants near line 640).
- Real payloads: `../Waveguide Generator/server/data/simulations.db`, table `simulation_jobs`, column `config_json`; the geometry payload for the viewport call is inside it (inspect its `mesh` key — top-level keys are `[advanced_settings, device_mode, frequency_range, ..., mesh, ...]`). Also mine `../Waveguide Generator/server/tests/` (e.g. `test_freeform_server.py`) and `../Waveguide Generator/tests/fixtures/` for valid FREEFORM/OSSE payload shapes. Real results: table `simulation_results.results_json` with keys `[di, directivity, frequencies, impedance, metadata, spl_on_axis]` — pick the row with the largest payload for chart data.

## Deliverables (all under `spike/`)

1. **`payloads/extract_payloads.py`** — builds `payloads/{osse,rosse,icw,freeform}.json`, each a valid `build_viewport_geometry` payload. Prefer real ones mined from the DB/tests; construct minimal valid ones from v1 defaults where missing. If ICW genuinely can't be constructed, emit a `payloads/MISSING-icw.md` explaining exactly why. Each payload must actually pass a smoke call to `build_viewport_geometry` before being written. Search hints for ICW: grep `ICW` under `../Waveguide Generator/server/` and `../Waveguide Generator/src/config/`.
2. **`bench_preview.py`** — the latency matrix. For each family × LOD (coarse: angularSegments/lengthSegments at their minimum clamp; fine: defaults) measure: cold (fresh subprocess: interpreter start + imports + first call, reported separately) and warm (N=40 in-process, p50/p95/max ms). Also report payload→frame encode time and frame byte size using `frame_codec`. Output `results/preview-timings.json` + a readable `results/preview-timings.md` table. Exit nonzero if any family errors.
3. **`frame_codec.py`** — binary frame v0: `MAGIC=b"WGF0"`, then u32 header length, then UTF-8 JSON header `{v:0, seq, evalMs, sections:[{name,dtype,shape,offset,byteLength}]}`, then packed little-endian buffers. `encode(seq, eval_ms, arrays: dict[str, np.ndarray]) -> bytes`, `decode(bytes) -> (header, dict[str, np.ndarray])`. Plus `grid_to_mesh(viewport_result) -> {positions: float32 (N,3) flat, indices: uint32}` triangulating the horn point grid (two triangles per quad cell; include the outer-wall grid if present as a second section). Include `test_frame_codec.py` (plain asserts, runnable with the venv python) covering round-trip + a known 3×3 grid triangulation.
4. **`ws_server.py`** — FastAPI app, port 3199, run via the v1 venv's uvicorn. Endpoints:
   - `GET /` → `static/index.html`; serve `static/` (and nothing else).
   - `WS /ws/preview`: client sends JSON `{seq, family, lod, paramOverride?}` where `paramOverride` is a single scalar param tweak (e.g. throat angle factor) applied to the stored payload so a sweep actually changes geometry. **Latest-wins coalescing: one compute in flight; while busy, keep only the newest queued request and drop older ones (send `{type:"dropped", seq}` JSON for dropped seqs).** Reply per computed request: binary frame from `frame_codec` (header carries `seq` and server `evalMs`).
   - `GET /api/results/real` → the largest `results_json` from the v1 DB (read-only URI), verbatim.
   - Startup: pre-warm (import adapter, one call per family) so first WS request isn't an import cliff; log pre-warm ms.
5. **`static/index.html` + `static/preview.js`** — three.js (import `./vendor/three.module.js`) page: dark background, renders the decoded mesh (BufferGeometry, reuse buffers when sizes match), OrbitControls NOT needed. Controls: family dropdown, LOD toggle, a param slider, and **"Run 10 s sweep"**: drives the slider programmatically at 30 Hz, sending seq-stamped requests. Collect per-frame: server evalMs (from header), decode ms, upload+draw ms (rAF delta), end-to-end request→painted ms, dropped count. After the sweep, render a stats table (p50/p95/max per metric + frames painted + fps) into `<pre id="stats">` as both a table and one JSON line, and `console.log` the JSON too.
6. **`static/charts.html` + `static/charts.js`** — ECharts (import `./vendor/echarts.esm.min.js`) validation against real data from `/api/results/real`: (a) FR overlay — on-axis SPL plus enough offset copies to reach 20 series, log-x; (b) directivity heatmap (angle × freq, dB colormap) from the `directivity` dict; (c) polar section at a slider-chosen frequency. A **"Measure"** button runs scripted hover/zoom/slider interactions for ~5 s and writes p50/p95 frame ms into `<pre id="stats">` (JSON line included). Note real data limits honestly (e.g. only 20 frequencies) in the page.
7. **`README.md`** — exact run commands for everything (venv python path spelled out), port, and a "Windows box: run this" section (same commands, Windows paths) so the second latency baseline can be captured later.

## Rules

- Python: type hints, small modules, no new dependencies beyond the v1 venv's existing packages. JS: plain ES modules, no build step, no fetches to the internet (vendor files only).
- You may run `bench_preview.py` and the codec test yourself to verify (keep N small when self-testing). Do NOT start uvicorn or any long-running server — the overseer runs those.
- Everything must work when the overseer runs: `"../Waveguide Generator/.venv/bin/python" spike/bench_preview.py` and `"../Waveguide Generator/.venv/bin/python" -m uvicorn ws_server:app --port 3199` from `spike/`.
- If `build_viewport_geometry` import drags in heavy/side-effectful modules, isolate the minimal import path and document it in README.
- Keep total exploration bounded; when unsure between two payload shapes, smoke-test both against the real function and keep the one that works.
